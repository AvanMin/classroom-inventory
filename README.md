# Система учёта инвентаря компьютерных классов

Консольное приложение на Python для учёта компьютерного оборудования в учебных кабинетах.

## Возможности

- просмотр списка оборудования;
- добавление, изменение и удаление записей;
- поиск по инвентарному номеру и кабинету;
- фильтрация по кабинету и/или состоянию;
- сохранение данных в JSON между запусками.

## Архитектура проекта

Приложение построено по принципу разделения ответственности (Separation of Concerns) и состоит из трёх независимых модулей:

1. `main.py` (Слой представления / CLI):
   - Отвечает исключительно за текстовое меню, форматированный вывод таблиц/карточек и чтение пользовательского ввода.
   - Изолирует бизнес-логику от обработки исключений терминала (`KeyboardInterrupt`, `EOFError`) и некорректных нажатий.

2. `inventory.py` (Модель данных и бизнес-логика):
   - `Equipment` — неизменяемый дата-класс (`@dataclass(frozen=True, slots=True)`), представляющий одну инвентарную запись. Валидация обязательных полей и допустимых состояний выполняется при инициализации в `__post_init__`. Редактирование записи возможно только через создание новой копии (`dataclasses.replace`), что исключает неконтролируемое изменение данных в памяти.
   - `Inventory` — контейнер в памяти, реализующий CRUD-операции, проверку уникальности инвентарного номера (без учёта регистра), поиск по номеру/кабинету и комбинированную фильтрацию.

3. `storage.py` (Слой хранения данных):
   - Инкапсулирует сериализацию в JSON (`data/inventory.json`) и десериализацию при старте программы.
   - Реализует безопасную загрузку: отсутствие файла, пустой файл или повреждённый JSON не приводят к аварийному завершению работы, а битые отдельные записи пропускаются с выводом предупреждения.
   - Реализует атомарную запись: данные сначала записываются во временный файл `.tmp`, после чего заменяют основной файл через `Path.replace()`, защищая справочник от потери данных при сбое во время сохранения.

## Инструкция пользователя

### 1. Системные требования
* Python версии 3.11 или новее.
* Git — только если вы планируете скачивать проект через консоль (необязательно, можно скачать архивом с сайта).
* *(Опционально)* Docker — для запуска программы в изолированном контейнере.

### 2. Установка и запуск

#### Шаг 1. Получение файлов проекта
Выберите любой удобный способ:

* Способ 1. Скачать архивом с GitHub (если не установлен Git)
1. Откройте страницу репозитория на GitHub(https://github.com/AvanMin/classroom-inventory) в браузере.
2. Нажмите зелёную кнопку `<> Code` и выберите `Download ZIP`.
3. Распакуйте скачанный архив в любую удобную папку.
4. Откройте эту папку в терминале (командной строке) или в редакторе кода (VS Code / PyCharm).

* Способ 2. Клонировать через Git (для разработчиков)
  Откройте терминал и выполните команды:
  ```bash
  git clone <ссылка_на_ваш_репозиторий>
  cd <папка_проекта>
  ```

#### Шаг 2. Настройка окружения и запуск программы
Находясь в папке с проектом в терминале, выполните следующие действия:

1. Создайте и активируйте виртуальное окружение (`venv`), чтобы изолировать зависимости проекта:
   * Windows:
     ```bash
     python -m venv venv
     venv\Scripts\activate
     ```
   * Linux / macOS:
     ```bash
     python3 -m venv venv
     source venv/bin/activate
     ```
2. Установите зависимости из файла `requirements.txt`:
   ```bash
   pip install -r requirements.txt
   ```
3. Запустите программу:
   ```bash
   python main.py
   ```

*(Дополнительно: если у вас установлен Docker, вместо Шага 2 можно собрать и запустить контейнер командами `docker build -t inventory-app .` и `docker run -it inventory-app`. Флаг `-it` обязателен для работы с интерактивным меню).*

### 3. Как пользоваться программой

После запуска на экране появится главное текстовое меню. Введите цифру нужного пункта и нажмите Enter:

* `1` — Показать всё оборудование
  Выводит полный список техники из базы с указанием инвентарного номера, типа, названия, кабинета и текущего состояния. Если база пуста, система сообщит об этом.
* `2` — Добавить новую запись
  Пошагово запрашивает данные о технике.
* `3` — Найти оборудование
  Позволяет быстро найти карточку устройства по его уникальному инвентарному номеру (или отфильтровать по кабинету, если функция добавлена). Если номер не найден, выведется соответствующее предупреждение.
* `4` — Изменить запись
  Запрашивает инвентарный номер существующего устройства и позволяет обновить его кабинет (при переносе техники) или состояние (например, если компьютер сломался).
* `5` — Удалить запись
  Удаляет карточку оборудования по инвентарному номеру. Для защиты от случайного удаления программа попросит подтверждение: введите `Y` (да) или `N` (отмена).
* `6` — Фильтр по кабинету/состоянию
* `0` — Выход
  Корректно завершает работу приложения.

### 4. Хранение данных и поведение при ошибках

* Автосохранение: Все изменения записываются в файл `data/inventory.json` сразу после выполнения операций. При следующем запуске данные подгружаются автоматически.
* Первый запуск / удаление файла: Если папки `data/` или файла `inventory.json` нет, программа создаст их автоматически при старте.
* Повреждение файла данных: Если `data/inventory.json` был отредактирован вручную с ошибкой синтаксиса, при запуске программа не «упадёт», а выведет предупреждение о повреждении файла, чтобы не перезаписать ваши данные вслепую.

### 5. Известные ограничения системы

1. Только консольный интерфейс (CLI): Управление происходит исключительно с клавиатуры в терминале; графический интерфейс и управление мышью не поддерживаются.
2. Локальное хранение без облачной синхронизации: Вся база находится в одном файле `data/inventory.json`. При физическом удалении этого файла без резервной копии данные восстанавливаются только с нуля.
3. Однопользовательский режим: Программа не рассчитана на одновременный запуск и редактирование одного файла `inventory.json` несколькими людьми по сети.
4. Отсутствие истории изменений (логов аудита): Система хранит только актуальное состояние карточки (кто и когда перенёс компьютер из кабинета в кабинет, в базе не фиксируется).
5. Ограниченный поиск: Поиск ориентирован на точное совпадение инвентарного номера (частичный или нечёткий поиск с опечатками не поддерживается).
