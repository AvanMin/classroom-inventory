# Система учёта инвентаря компьютерных классов

Командный проект: консольное приложение на Python для учёта оборудования
компьютерных классов. Данный репозиторий содержит **часть роли Lead Developer
(LD) за спринт 1**.

## Что сделано в спринте 1 (LD)

Задача LD по плану: создать структуру проекта, набросать меню и модель записи,
реализовать запуск приложения и пункт «Показать оборудование» на
демонстрационных данных.

- [x] Структура проекта: `main.py`, `inventory.py`, `data/`, `tests/`
- [x] Модель записи `Equipment` (инвентарный номер, тип, наименование,
      кабинет, состояние, дата поступления, ответственное лицо)
- [x] Главное меню с зарезервированными пунктами под следующие спринты
- [x] Запуск приложения и рабочий пункт «Показать оборудование»
- [x] 8 демонстрационных записей (требование Definition of Done: не менее 5)

## Требования

- Python 3.11 или новее
- Внешние библиотеки для запуска не нужны (только стандартная библиотека)

## Запуск

```bash
python main.py
```

В Windows можно запустить двойным щелчком по `run.bat` (он включает
кодировку UTF-8 и запускает `main.py`).

| Пункт | Действие | Статус |
|-------|----------|--------|
| 1 | Показать оборудование | работает (демонстрационные данные) |
| 2 | Добавить запись | спринт 2 |
| 3 | Найти оборудование | спринт 3 |

а команда заранее видит план работ.

## Модель записи

| Поле | Обязательное | Формат |
|------|--------------|--------|
| `inventory_number` | да | 2–32 символа, уникальный |
| `kind` | да | например: ПК, монитор, принтер, МФУ |
| `name` | да | наименование оборудования |
| `room` | да | номер кабинета, например `204` |
| `state` | да | `исправно`, `требует ремонта`, `списано` |
| `received_at` | нет | дата в формате ISO `YYYY-MM-DD` |
| `responsible` | нет | ФИО ответственного |

Для будущего JSON-файла предусмотрены `Equipment.to_dict()` и
`Equipment.from_dict()`: поле `kind` в файле называется `type`.

## Ограничения спринта 1

- Данные хранятся только в памяти и берутся из `DEMO_RECORDS`;
  изменения не сохраняются между запусками (JSON — спринт 4).
- Добавление, поиск, изменение и удаление ещё не реализованы.
- Автотесты пишет роль QA; в `tests/` пока только заготовка каталога.
