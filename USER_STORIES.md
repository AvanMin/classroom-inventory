# User Stories — Система учёта инвентаря компьютерных классов

## Описание проблемы

В колледже отсутствует единая система учёта компьютерного оборудования. Информация об инвентарных номерах, кабинетах, состоянии техники и ответственных лицах хранится разрозненно (в тетрадях, Excel-файлах, устно). Из-за этого часто теряется актуальная информация: сложно быстро найти нужный компьютер, понять его состояние, узнать, в каком кабинете он находится и кто за него отвечает.

## Цель проекта

Разработать консольное приложение на Python для учёта компьютерного оборудования с возможностью просмотра, добавления, поиска, изменения и удаления записей, фильтрации, а также сохранения данных между запусками.

## User Stories

### US-01. Просмотр списка оборудования
**Как** лаборант,  
**я хочу** просматривать список всего оборудования,  
**чтобы** быстро понимать, какая техника есть в наличии и в каком она состоянии.

**Критерии приёмки:**
- При выборе пункта «Показать оборудование» выводится список всех записей.
- В списке отображаются: инвентарный номер, тип, наименование, кабинет, состояние.
- Если записей нет — выводится понятное сообщение.

**Статус:** ПРИНЯТО (Спринт 5).

---

### US-02. Добавление оборудования
**Как** лаборант,  
**я хочу** добавлять новую единицу оборудования,  
**чтобы** вести актуальный учёт поступающей техники.

**Критерии приёмки:**
- Можно ввести инвентарный номер, тип, наименование, кабинет и состояние.
- Нельзя добавить запись с уже существующим инвентарным номером.
- При пустых обязательных полях программа сообщает об ошибке и не создаёт запись.
- Программа не завершается аварийно при некорректном вводе.

**Статус:** ПРИНЯТО (Спринт 5).

---

### US-03. Поиск оборудования
**Как** лаборант,  
**я хочу** искать оборудование по инвентарному номеру и кабинету,  
**чтобы** быстро найти нужную единицу и узнать, где она находится.

**Критерии приёмки:**
- Поиск по существующему номеру показывает карточку оборудования.
- По несуществующему номеру выводится сообщение «Не найдено».
- Пустой ввод не приводит к аварийному завершению программы.
- Реализован поиск по кабинету (подстрока, без учёта регистра).

**Статус:** ПРИНЯТО (Спринт 5).

---

### US-04. Изменение данных об оборудовании
**Как** лаборант,  
**я хочу** изменять данные об оборудовании (кабинет, состояние),  
**чтобы** поддерживать информацию в актуальном состоянии.

**Критерии приёмки:**
- Можно найти запись и изменить кабинет и/или состояние.
- После изменения данные корректно отображаются при следующем просмотре.
- При попытке изменить несуществующую запись программа сообщает об ошибке.
- Исходный объект `Equipment` не мутируется (frozen dataclass).

**Статус:** ПРИНЯТО (Спринт 5).

---

### US-05. Удаление оборудования
**Как** лаборант,  
**я хочу** удалять списанное или ошибочно добавленное оборудование,  
**чтобы** в базе не было лишних записей.

**Критерии приёмки:**
- Перед удалением программа запрашивает подтверждение.
- После подтверждения запись исчезает из списка.
- При отмене удаления запись остаётся.
- Обрабатывается ситуация, когда пользователь пытается удалить несуществующую запись.

**Статус:** ПРИНЯТО (Спринт 5).

---

### US-06. Сохранение данных между запусками
**Как** администратор / заведующий,  
**я хочу**, чтобы данные сохранялись между запусками программы,  
**чтобы** не вводить информацию заново каждый раз.

**Критерии приёмки:**
- После перезапуска программы все ранее добавленные записи остаются.
- При первом запуске (если файла данных ещё нет) программа корректно стартует.
- Повреждённый или отсутствующий файл обрабатывается безопасно.
- Сохранение атомарное (через временный файл), старый файл не повреждается при ошибке.

**Статус:** ПРИНЯТО (Спринт 5, усилено в Спринте 6).

---

### US-07. Фильтрация оборудования
**Как** проверяющий,  
**я хочу** фильтровать технику по конкретному кабинету и/или состоянию,  
**чтобы** быстро проводить инвентаризацию в одной аудитории.

**Критерии приёмки:**
- Можно указать только кабинет, только состояние или оба параметра.
- Пустое значение не учитывается как критерий.
- Результат сортируется по инвентарному номеру.
- Если ничего не найдено — выводится понятное сообщение.

**Статус:** ПРИНЯТО (Спринт 6).

---

### US-08. Безопасный выход
**Как** пользователь,  
**я хочу** безопасно завершать программу через `Ctrl+C` или пункт «Выход»,  
**чтобы** не повредить JSON-файл.

**Критерии приёмки:**
- `Ctrl+C` и `EOF` в любом диалоге обрабатываются и не приводят к падению.
- Выход по `0` / `q` / `выход` завершает программу с кодом 0.
- Данные сохраняются после каждой мутирующей операции, поэтому выход не требует дополнительного сохранения.

**Статус:** ПРИНЯТО (Спринт 6).

## Спринт 2: Уточнённые требования и тестовые данные

### Правила заполнения полей
- **Инвентарный номер:** обязательное, уникальное, нормализуется в верхний регистр.
- **Тип:** обязательное (ПК, монитор, принтер и др.).
- **Наименование:** обязательное.
- **Кабинет:** обязательное.
- **Состояние:** обязательное, одно из `исправно`, `требует ремонта`, `списано`.
- **Дата поступления:** опционально, ISO `YYYY-MM-DD`.
- **Ответственный:** опционально.

### Примеры для тестирования
**Корректные данные:**
- Номер: PC-0101 | Тип: ПК | Наименование: Dell Optiplex | Кабинет: 315 | Состояние: исправно
- Номер: MON-0102 | Тип: монитор | Наименование: LG 24" | Кабинет: 315 | Состояние: исправно

**Ошибочные данные:**
- Дубликат номера PC-0101.
- Пустой кабинет или наименование.
- Недопустимое состояние (`сломано`).

## Спринт 3: Сценарии поиска, редактирования и удаления

### Сценарии поиска
1. **Поиск по инвентарному номеру:** карточка или сообщение об отсутствии.
2. **Поиск по кабинету:** список всего оборудования в кабинете (подстрока, без учёта регистра).

### Правила подтверждения удаления
1. Программа запрашивает инвентарный номер.
2. Если запись найдена — показывает карточку и спрашивает подтверждение.
3. `y/yes/да/д` — удаление и сохранение.
4. Любой другой ввод — «Удаление отменено».
5. Номер не найден — «Запись с таким номером не найдена».
